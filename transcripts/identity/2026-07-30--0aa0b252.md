**Q:**

> Are wildcards supported in redirect URIs

**A:**

```markdown
**No, wildcards are not supported in redirect URIs.**

Redirect URIs must use exact match - you need to specify the complete, exact URL where users will be redirected after authentication. The platform requires HTTPS for all redirect URIs (except for localhost during development).

**Technical Details:**

When configuring your application client, you must provide the full redirect URI without any wildcard patterns. For example:
- ✅ `https://myapp.example.com/callback`
- ❌ `https://*.example.com/callback`

However, if you're using **credential templates**, the `redirectUris` field does support **Handlebars template syntax** with mustache notation. This allows you to use variables for dynamic URI construction. For example:
- Template: `{{example}}/hello`
- With variable `example=https://example.com`
- Resolves to: `https://example.com/hello`

This templating approach can help manage multiple similar URIs across different environments, but each resolved URI must still be a complete, exact URL.

For more details, see the Identity documentation at https://docs.tylerdev.io/identity
```
