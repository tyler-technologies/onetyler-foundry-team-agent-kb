**Q:**

> What are client operations?

**A:**

```markdown
**Client Operations** is a feature that enables basic management of manually created clients in the Tyler Identity platform. Think of it as a secure way to maintain your application's credentials and settings without needing to submit a ticket every time.

## What You Can Do

Client Operations supports three key management tasks:

1. **Rotate Secret** - Generate new client secrets with a 3-day grace period for the old secret
2. **Update Redirects** - Modify redirect URIs and post-logout redirect URIs (supports wildcard subdomains)
3. **Expunge Old Secrets** - Remove all expired secrets except the most recent one

## Who It's For

This is primarily for teams that have **manually created tid-gateway clients** (not automatically provisioned clients). **Note:** Okta clients are not supported.

## How It Works (Technical Details)

Security is enforced through two mechanisms:
- An OAuth2 token with the `tidgateway:client-operations` scope
- A **one-time-use operations token** unique to each client

Each successful request consumes the operations token and returns a new one - this ensures each operation is authorized individually.

## Best Practice

Applications should **not** manage their own secrets directly. Instead, use a secure provisioning or orchestrator service to:
- Store operations tokens securely
- Handle secret rotation
- Distribute updated configurations

This follows the principles of **Separation of Duties** and **Least Privilege**.

## Getting Started

To enable client operations, submit a ticket to the Tyler Identity Team with your existing client name and request type set to "Enable Client Operations."

For more details, see the full documentation at: https://docs.tylerdev.io/identity (navigate to Shared Guides > Client Operations)
```
