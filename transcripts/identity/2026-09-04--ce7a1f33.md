**Q:**

> what is the parameter that applications must pass in calls to the Gateway so it know which organization is being accessed?

**A:**

```markdown
**Simple Answer:**

Applications must pass either **`organizationKey`** or **`workspaceKey`** as a query parameter when redirecting to the Gateway's `/authorize` endpoint. The **`workspaceKey` is preferred** because it allows the Gateway to resolve both the workspace and the organization, resulting in better security practices.

---

**Technical Details:**

When your application redirects users to authenticate, include one of these custom query parameters:

- **`workspaceKey`** — (preferred) the specific workspace identifier for an organization (e.g., "demo-test")
- **`organizationKey`** — the organization's identifier (e.g., "demo")

**Why this matters:**
Most Tyler applications are "organization-forward," meaning the organization or workspace is indicated in the URL (like a subdomain) or the deployment. This login context ensures the Gateway routes authentication to the correct customer IdP.

**How it appears in tokens:**

In the `id_token`:
```json
{
  "organizationKey": "demo",
  "workspaceKey": "demo-test"
}
```

In the `access_token` (as scopes):
```json
{
  "scope": "app-read-scope org:demo wks:demo-test"
}
```

You can get these identifier values from **Ops Center**.

For more details, see the [Login Context with Identity Workforce](https://docs.tylerdev.io/identity) documentation in the [Docusaurus-Identity.md](/api/tenant-knowledge-base/collections/TCP-KB-Identity/files/0c056ff0-f664-4262-839a-c70ffa59df85/download).
```
