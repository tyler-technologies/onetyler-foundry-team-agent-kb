**Q:**

> Your request resulted in an error. Clients with 'application_type' of 'service' are not allowed to access the 'authorize' endpoint.

**A:**

```markdown
This error occurs when you're trying to use a **service client** (machine-to-machine client) with the authorization endpoint, which is designed for interactive user authentication flows.

## Quick Explanation

Service clients are meant for server-to-server communication and use the **Client Credentials flow**. They can't access the `/authorize` endpoint because that endpoint is for flows where a user logs in interactively (like Authorization Code or Implicit flows).

## How to Fix This

**If you need machine-to-machine authentication:**
- Use the `/token` endpoint directly with the Client Credentials grant
- Your request should look like:
  ```
  POST /token
  grant_type=client_credentials
  client_id=your_client_id
  client_secret=your_client_secret
  scope=your_requested_scopes
  ```

**If you need user authentication:**
- You're using the wrong client type. Create or use a client with `application_type` set to:
  - `web` - for server-side web applications
  - `spa` - for single-page applications
  - `native` - for mobile/desktop apps

## Technical Details

Let me search for more specific information about client types and their allowed flows:

Based on the documentation, here's what you need to know:

## Application Types and Their Allowed Flows

When registering a client, the **Application Type** determines which OAuth2/OIDC flows are available:

- **Web** - Server-side web applications → Authorization Code Flow
- **SPA** - Single-page applications → Authorization Code Flow + PKCE
- **Native** - Mobile/desktop apps → Authorization Code Flow + PKCE  
- **Service** - Machine-to-machine → **Client Credentials Flow ONLY**

## Why Service Clients Can't Use /authorize

Service clients are designed for **backend API-to-API communication** without user interaction. The `/authorize` endpoint requires a user to log in, which doesn't make sense for service accounts.

## When to Use Each Type

**Use Client Credentials Flow (Service client) for:**
- Backend API to API communication
- Scheduled jobs and batch processes
- Service accounts acting on their own behalf
- System-to-system integration

**Do NOT use Client Credentials Flow for:**
- User-facing authentication (use Authorization Code Flow instead)
- Scenarios where you need user identity or `organizationKey` context

## Solution

Check your client registration and ensure the `application_type` matches your use case. If you need user authentication, you'll need a different client (Web, SPA, or Native type) that supports the Authorization Code Flow.

For more details, see the documentation at: https://docs.tylerdev.io/identity
```
