## 1. OIDC Configuration

**Redirect URI:**
When integrating FusionAuth as a customer IdP with TID (Tyler Identity), the redirect URI would be:
- **Authorization endpoint**: `{authority}/oauth2/authorize`
- **Token endpoint**: `{authority}/oauth2/token`

Where `{authority}` is the Gateway URL (e.g., `https://idgw.tylerportico.com/tg` for production).

**OIDC Discovery:**
✅ **Yes, TID fully supports OIDC Discovery** at `{authority}/.well-known/openid-configuration`

Standard endpoints exposed:
- Authorization: `{authority}/oauth2/authorize`
- Token: `{authority}/oauth2/token`
- UserInfo: `{authority}/oauth2/userinfo`
- JWKS: `{authority}/oauth2/v1/keys`
- End Session: `{authority}/oauth2/v1/logout`

**Grant Types:**
TID supports:
- ✅ **Authorization Code** (primary, recommended)
- ✅ **Authorization Code + PKCE** (strongly recommended for all clients)
- `refresh_token` grant
- `client_credentials` (for service accounts)

---

## 2. Token Handling

**Token Consumption:**
TID **consumes both ID Token and Access Token**. The typical flow:
- ID Token contains user identity claims (5-minute expiration)
- Access Token used for API authorization (60-minute max lifetime)

**UserInfo Endpoint:**
Yes, TID can call `/oauth2/userinfo`. From the docs:
> "To retrieve the full set of claims for login, you must include these three scopes: `openid`, `email`, `profile`. Enable 'get claims from UserInfo endpoint' in your OIDC configuration."

**Required Claims:**
Key claims TID expects in tokens:
- `sub` - Subject/unique user identifier
- `preferred_username` - Username for the user
- `email` - User's email address
- `name`, `given_name`, `family_name` - User profile information
- **`organizationKey`** - Critical for routing (this would need to be mapped from FusionAuth)

---

## 3. Domain-Based Routing

**How TID Routes:**
TID uses the **`organizationKey` parameter** for routing to the correct IdP. From the documentation:

> "The `organizationKey` is **critical** for Gateway routing:
> - Obtained from Ops Center for each customer
> - Routes authentication to the customer's configured IdP
> - Must be included in every authorization request"

**Hints/Parameters:**
TID doesn't use `login_hint` or `domain_hint` in the standard way. Instead, it uses:
- `organizationKey` parameter in the authorization request
- This must be added programmatically to every `/authorize` call

**Multi-tenancy:**
The documentation supports **federation of multiple customer IdPs through a single Gateway**. Each organization would have their own IdP configuration, not separate FusionAuth tenants necessarily—the Gateway routes based on `organizationKey`.

## 5. Session & Logout

**Single Logout (SLO):**
✅ **Yes, TID supports federated logout**

Logout endpoint: `{authority}/oauth2/v1/logout`

Parameters:
```http
GET {authority}/oauth2/v1/logout?
  id_token_hint={user_id_token}
  &post_logout_redirect_uri={your_post_logout_uri}
```

**Session Termination:**
The Gateway supports **front-channel logout notifications** to participating applications within a session.

⚠️ **Important caveat**: "Not all IdPs support federated logout" - you'd need to ensure FusionAuth is configured to support this.

## 6. Security & Token Validation

**Token Validation Method:**
TID validates tokens **locally using JWKS**. Applications should:

```csharp
options.Authority = "https://idgw.tylerportico.com/tg";
options.TokenValidationParameters = new TokenValidationParameters {
    ValidateIssuer = true,
    ValidIssuer = "https://idgw.tylerportico.com/tg",
    ValidateAudience = false, // Gateway uses static audience
    ValidateLifetime = true,
    ValidateIssuerSigningKey = true
};
```

**Token Expiry:**
- **ID Tokens**: Typically 5 minutes
- **Access Tokens**: Maximum lifetime is **60 minutes**
- **Refresh Tokens**: Typically 90 days
