## Dual Trust

**Dual Trust** is a security pattern that allows your APIs to accept and validate tokens from two different identity providers at the same time. This is particularly useful during migration periods when you're transitioning from a legacy identity system to the Identity Gateway.

### Why Use Dual Trust?

When migrating to the Identity Gateway, you may have:
- Some users still authenticating through your old/legacy identity provider
- Other users already using the new Identity Gateway
- A need to support both during the transition period without disrupting service

### How It Works

Your API is configured to trust tokens from both sources simultaneously. When a request comes in with a token, your API validates it against either the Gateway or your legacy identity provider, whichever issued it.

---

### Technical Implementation (.NET)

Here's how to configure dual trust in an ASP.NET application:

```csharp
services.AddAuthentication()
    .AddJwtBearer("Gateway", options => 
    {
        options.Authority = "https://idgw.tylerportico.com/tg";
    })
    .AddJwtBearer("Legacy", options => 
    {
        options.Authority = "https://legacy-idp.com";
    });

services.AddAuthorization(options => 
{
    options.DefaultPolicy = new AuthorizationPolicyBuilder()
        .RequireAuthenticatedUser()
        .AddAuthenticationSchemes("Gateway", "Legacy")
        .Build();
});
```

This configuration:
1. Registers two JWT Bearer authentication schemes - one for the Gateway and one for your legacy IdP
2. Creates an authorization policy that accepts tokens from either scheme
3. Allows your API to validate tokens from both sources during the migration

**Learn more:** [Identity Workforce Integration Guide](https://docs.tylerdev.io/identity/workforce)
```
