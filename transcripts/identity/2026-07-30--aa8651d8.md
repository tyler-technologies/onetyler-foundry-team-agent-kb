> How do you call the User Info Endpoint?

**A:**

## How to Call the User Info Endpoint

To call the User Info Endpoint, you make an HTTP GET request to the UserInfo endpoint URL with a valid access token.

**Simple answer:**
1. Get an access token from the token endpoint (after successful authentication)
2. Make a GET request to the UserInfo endpoint: `{okta_authority}/oauth2/userinfo`
3. Include the access token in the Authorization header as a Bearer token

**Technical details:**

### Endpoint URL
- **UserInfo**: `{okta_authority}/oauth2/userinfo`

### Required Scopes
To retrieve the full set of user claims, you must include these three scopes in your authorization request:
- `openid`
- `email`
- `profile`

### Configuration
Enable "get claims from UserInfo endpoint" in your OIDC configuration.

### Example Response
The UserInfo endpoint returns user profile information like this:
```json
{
  "sub": "00uz5pj5m5JswzW3G0h7",
  "preferred_username": "[REDACTED-EMAIL]",
  "home_org": "demo",
  "given_name": "Jason",
  "family_name": "Howard",
  "email": "[REDACTED-EMAIL]",
  "name": "Jason Howard",
  "crmid": "demo"
}
```

For more details, see the [Tyler Identity documentation](https://docs.tylerdev.io/identity).

**Q:**

> is get claims from UserInfo a part of Dynamic Auth or part of OIDC?

**A:**

```markdown
"Get claims from UserInfo endpoint" is part of **standard OIDC configuration**, not specific to Dynamic Auth.

**Simple answer:**
It's a standard OIDC setting that tells your OIDC client library to retrieve user profile claims by calling the UserInfo endpoint, rather than only relying on claims in the ID token. This is a configuration option available in most OIDC libraries.

**More detail:**

- **OIDC Standard**: The UserInfo endpoint is part of the OpenID Connect specification. The setting to "get claims from UserInfo endpoint" is a configuration option in OIDC client libraries (like Microsoft's OIDC middleware)

- **Dynamic Auth**: This is a Tyler-specific .NET library that simplifies Gateway integration for ASP.NET applications. It handles things like automatic `organizationKey` handling, session management, and token refresh - but it still uses standard OIDC underneath

- **Configuration**: Whether you use Dynamic Auth or configure OIDC directly (like `Microsoft.AspNetCore.Authentication.OpenIdConnect`), you would enable this setting in your OIDC configuration to ensure you get the full set of user claims

So to summarize: the UserInfo endpoint and the option to retrieve claims from it are **standard OIDC features**. Dynamic Auth is just a convenience library that makes it easier to configure OIDC for Tyler's Gateway, but you can use any OIDC library and still access the UserInfo endpoint.

For more details, see the [Tyler Identity documentation](https://docs.tylerdev.io/identity).
```
