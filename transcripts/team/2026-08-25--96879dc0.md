## Federation & SSO Overview

Tyler Identity supports federation for both **Workforce** (employee/staff users) and **Community** (citizen/public users) scenarios:

### **Identity Workforce Federation**
For back-office and enterprise applications, the **Identity Gateway** federates with your customer's own Identity Provider. This means employees authenticate using their organization's existing identity system.

**Supported Protocols:**
- **OIDC (OpenID Connect)**
- **SAML 2.0**

Your Tyler application integrates with the Gateway using OIDC, and the Gateway handles the federation to the customer's IdP using either OIDC or SAML as configured in Admin Center.

**Customer IdP Requirements:**
- Must be externally accessible from the public internet
- Must support either OIDC or SAML2 protocols
- Must be highly redundant and scalable
- Must be from a trusted industry vendor

**Common Customer IdPs:**
- Microsoft Entra ID (formerly Azure AD)
- Ping Identity
- Rapid Identity
- Duo SSO
- Google Workspace
- OneLogin
- Thales SafeNet Trusted Access
- ForgeRock

### **Community Access Federation**
For citizen-facing applications, Community Access uses a single Tyler-managed Okta tenant. You can also federate with state or jurisdictional Identity Providers using the `idp` parameter to route users directly to their organization's IdP, bypassing the Okta login screen.

---

## How Does It Work?

**For Workforce applications:**
1. Your application sends users to the Identity Gateway with an `organizationKey` parameter
2. The Gateway routes the user to their organization's configured IdP
3. User authenticates at their own IdP (e.g., Entra ID)
4. Gateway receives authentication confirmation
5. Gateway issues tokens back to your application

This provides **single sign-on** across all Tyler workforce applications using the same Gateway authority.

---

## Need More Specific Help?

Are you:
- **Setting up a new federation** with a customer IdP?
- **Troubleshooting** an existing SSO connection?
- **Configuring SAML or OIDC** settings in Admin Center?
- **Understanding how to route users** to their IdP?

Let me know what you're trying to accomplish and I can provide more detailed guidance!

You can find more details in the [Tyler Identity documentation](https://docs.tylerdev.io/identity).
