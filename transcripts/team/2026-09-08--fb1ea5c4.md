Thank you for clarifying! Since you're asking about **retargeting a workspace to a Gateway**, this is an **Ops Center** topic. Let me search for the specific information you need.Perfect! I found detailed information about retargeting a workspace to Gateway. Here's how to do it:

## Retargeting a Workspace to Gateway (Ops Center)

### Overview
**Retargeting** is a Tyler staff-only operation that sets a flag on a workspace telling deployment tools to configure products to use Gateway settings instead of Okta. This is part of the Workforce Managed to Workforce Direct migration process.

### Prerequisites
1. **Permission Required**: You must have the "Workspace Migration" permission in Ops Center. If you don't see the menu item, file a support ticket to request access.
2. **Coordinate with Product Teams**: Ensure they're ready to redeploy gateway-ready versions before you retarget.
3. **Validate Eligibility**: Confirm the organization meets migration requirements (no local accounts, etc.)

### Step-by-Step Process

#### Navigate to Workspace Migration
1. Open **Ops Center** → **Orgs** → Search for and select the customer organization
2. In the left sidebar, click **Workspace Migration**
   - URL pattern: `https://admin.{tcpci|tcpqa|tylerportico}.com/portal/ops-center/manage-organizations/<orgKey>/workspace-migration`
3. You'll see the org-level overview with:
   - **Workspace retargeting** table (all workspaces listed)
   - **Target Gateway** column (initially empty)
   - **Enable self-service migration** button (grayed out initially)

#### Retarget Each Workspace (Repeat for Each)
1. **Click into a workspace** from the table
2. Review the workspace details showing current **Target = Okta**
3. Read the **IMPORTANT warning panel** confirming you've validated:
   - Customer admins are aware and expecting this change
   - All workspaces will be retargeted
   - Non-TCP applications will be redeployed after retargeting
   - Applications will be tested after redeployment
4. **Coordinate with product teams** before proceeding
5. Click **Target Gateway**
6. **Confirm** the dialog warning about redeployment requirements
7. You'll see a success toast: *"Update workspace target success"*
8. The workspace now shows **Target = Gateway** with a ✓ in the overview table
9. **Product teams redeploy** gateway-ready versions and test
10. **Repeat** for each remaining workspace

#### Enable Self-Service Migration (After All Workspaces)
Once ALL workspaces show ✓ in the Target Gateway column:
1. Return to the org-level overview
2. The **Workspace retargeting** section shows a green **complete** badge
3. Click **Enable self-service migration** (now active)
4. Confirm the dialog
5. Customer can now complete Part 2 (federation migration) in Admin Center
