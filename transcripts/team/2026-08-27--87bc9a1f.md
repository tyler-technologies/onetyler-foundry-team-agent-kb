I'll search our Identity documentation for information about checking refresh tokens.Based on the Identity documentation, here's how to check/validate refresh tokens:

## Basic [redacted-token]

**Refresh tokens are validated when you use them.** There isn't a separate introspection endpoint to check if a refresh token is valid. The standard approach is to attempt to use the refresh token to get a new access token.

## Using a Refresh Token

To check if a refresh token is still valid, make a token request:

```http
POST {authority}/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token
&refresh_token=[redacted-secret]}
&client_id={your_client_id}
&client_secret=[REDACTED-CREDENTIAL]}
```

If the refresh token is valid, you'll receive new tokens. If it's invalid or expired, you'll get an error.

## Common Issues with Refresh Tokens

According to the [Identity documentation](/api/tenant-knowledge-base/collections/TCP-KB-Identity/files/0c056ff0-f664-4262-839a-c70ffa59df85/download), if your **"Refresh Token Not Working"**:

1. **Include `offline_access` scope** in your initial authorization request
2. **Check refresh token expiration** (typically 90 days)
3. **Verify client secret is correct** (for confidential clients)

## Best Practices

From the [token management checklist](/api/tenant-knowledge-base/collections/TCP-KB-Identity/files/0c056ff0-f664-4262-839a-c70ffa59df85/download):

- **Refresh tokens before expiration** (5 minutes recommended buffer)
- **Use refresh tokens with `offline_access` scope** for long-lived sessions
- **Store tokens securely** (httpOnly cookies for server-side, sessionStorage for SPAs)

---

**In summary:** To check a refresh token, attempt to use it in a token refresh request. If successful, it's valid; if it returns an error, it's expired or invalid. There's no separate validation endpoint.
