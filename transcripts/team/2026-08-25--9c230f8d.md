```markdown
Based on the documentation, the configuration is typically done **self-service in Admin Center** by the customer. However, the documentation doesn't provide the detailed step-by-step UI instructions for configuring federation in Admin Center. Let me provide what I know about the process:

## Federation Configuration Process

### **Overview**

For **Workforce Direct** with Entra ID, the customer's IT administrator configures the federation through **Admin Center** - Tyler's customer-facing administrative portal. This is typically a self-service process.

### **What the Customer Does in Admin Center**

The customer needs to:

1. **Access their Admin Center**
   - Their organization must already exist in Ops Center (Tyler's internal tool)
   - The IT Admin receives access credentials to their Admin Center instance

2. **Configure the IdP Federation**
   - Navigate to the Identity/IdP configuration section in Admin Center
   - Choose federation protocol: **OIDC** or **SAML2**

### **Configuration Details by Protocol**

**For OIDC Federation:**
They'll need to enter from their Entra ID:
- Client ID
- Client Secret
- Scopes (e.g., `openid profile email`)
- Issuer endpoint
- Authorization endpoint
- Token endpoint
- JWKS endpoint
- UserInfo endpoint

**For SAML Federation:**
They'll need to provide:
- IdP metadata URL (or upload the XML file)
- IdP certificate
- Configure SAML attribute mapping for:
  - Email
  - Username
  - First Name
  - Last Name

### **What the Customer Needs to Do in Entra ID**

On their Entra ID side, they need to:

1. **Register Tyler Gateway as a Service Provider/Application**
   - Create a new Enterprise Application or App Registration in Entra ID
   
2. **Configure the Tyler Gateway endpoints** (from my previous response):
   - Authority: `https://idgw.tylerportico.com/tg`
   - Redirect/Reply URLs as needed
   
3. **Configure Claims/Attributes**
   - Map Entra ID attributes to send Email, Username, First Name, Last Name

4. **Generate Credentials**
   - For OIDC: Client ID and Client Secret
   - For SAML: Metadata URL or downloadable XML

If the customer **cannot complete the federation through Admin Center** (technical issues, non-standard setup, etc.), you would file ticket **`4128` - Federate Identity Provider** with Tyler Identity.
```

**Q:**

> can the client access the admin center if the federtion has not been put in place

**A:**

```markdown
Great question! This is an important catch-22 situation. Based on the documentation, here's how it works:

## Yes - Initial Admin Center Access is Provided Before Federation

When a **new Workforce Direct organization is created**, the process includes providing initial access to the customer's IT administrator:

### **How Initial Access Works:**

1. **During Organization Creation**
   - When the org is created (via ticket `4158` or self-service +Import), you must provide:
     - **Customer Technical Contact Name** (First/Last name)
     - **Customer Technical Contact Email**
   
2. **The Customer IT Admin Receives Access**
   - This designated technical contact becomes the initial **Org Admin**
   - They receive Admin Center access credentials/instructions
   - This happens **before federation is configured**

3. **They Can Then Configure Federation**
   - With Admin Center access, they can set up the federation to their Entra ID
   - Once federation is complete, subsequent logins use their federated identity

### **The Bootstrap Flow:**

```
1. Org created in Ops Center
   ↓
2. Customer IT Admin designated (Technical Contact)
   ↓
3. IT Admin gets Admin Center access (pre-federation)
   ↓
4. IT Admin logs into Admin Center
   ↓
5. IT Admin configures Entra ID federation in Admin Center
   ↓
6. Federation active - future logins use Entra ID
```

### **Key Points:**

- ✅ **Initial access is NOT federated** - it's granted directly as an Org Admin
- ✅ The customer's **Technical Contact** specified during org creation gets this access
- ✅ This is specifically designed to solve the "chicken and egg" problem
- ✅ Once they configure federation, regular users authenticate through Entra ID

---

## If There's an Access Issue

If the customer's IT admin cannot access Admin Center initially, you can request their access via ticket **`4165` - Client Admin Center Access Request**:

- Requires: CRM Customer Identifier, customer's email, reason for access
- Used when the IT admin needs to be added or wasn't properly set up during org creation
```
