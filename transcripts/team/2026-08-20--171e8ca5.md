## What is CAPM?

**Community Access Profile Manager (CAPM)** is a client-facing application that allows authorized Tyler customers to find and look up a public user's **Identity Community** account.

## When to Use CAPM

CAPM is used when:
- A community (public) user needs support with their Identity Community account
- A customer IT admin needs to locate that account

## Important Notes

- **CAPM is separate from Admin Center** - it addresses Identity Community users, not Workforce users
- For detailed Identity Community questions, you should refer to the Identity agent documentation

To access CAPM, you would typically find it through your Tyler platform applications as an authorized customer IT administrator. The specific access URL and permissions would be configured through your organization's Tyler platform setup.

For more detailed information about Identity Community and related questions, I recommend consulting the Identity Implementation Assistant agent.

## How to Grant Access to CAPM

To grant a user access to CAPM (Community Access Profile Manager), you would typically use **Access Control Lists (ACLs)** if CAPM uses the ACL model. Here are the general steps:

### Prerequisites
1. **The user must have a Workforce user profile** in Admin Center > Users (add them if they don't exist yet)
2. **The user must be able to authenticate** (have valid credentials in an IDP associated with your organization)
3. **CAPM must be available** in your Workspace

### Creating or Modifying an ACL to Include CAPM

1. Go to **Admin Center > Access Control** (or **Workspaces > [Workspace] > Access Control**)
2. Either create a new ACL or select an existing one to modify
3. **Add the CAPM application** to the ACL (if it appears in the available applications list)
4. **Add the users** who need access to CAPM
5. Save your changes

### Important Notes
- Not all applications require ACLs - only products that use the ACL model
- If CAPM doesn't appear in your available applications list, you may need to contact Tyler support to enable it for your workspace
- Organization Admins are not automatically included in ACLs and must be added explicitly

For detailed Identity Community-related questions about CAPM, I recommend consulting the Identity Implementation Assistant agent.

## How Tyler Employees Grant Access to CAPM

Tyler employees **cannot directly "grant" access to CAPM** in the traditional sense. Instead, they must **request access** through **Support Access Center (SAC)**, and that access is either auto-approved or requires customer approval depending on the organization's settings.

### Prerequisites for Tyler Staff

1. **Any Tyler staff member with an `@tylertech.com` email** can log into SAC
2. **To request access to CAPM specifically**, the Tyler employee must:
   - Be added to an **SAC user group** that has been mapped to CAPM by the Support Council representative
   - If CAPM doesn't appear in the product list when making a request, contact your **Support Council rep** to be added to the appropriate group

### Steps to Request Access to CAPM

1. **Log into Support Access Center (SAC)**
2. **Start the "Request access" wizard** from the SAC Dashboard:

   **Access details tab:**
   - Select or enter the **Organization** and **Access through** values
   - Provide a **link to the support ticket** (from CRM or other justification)
   - Enter an **Access reason** for the customer to review
   - Click **Next**

   **Select products tab:**
   - Filter and select **CAPM** from the product list
   - (If CAPM doesn't appear, you're not in the right SAC group - contact your Support Council rep)
   - Click **Next**

   **Select workspaces tab:**
   - Select at least one workspace
   - Click **Next**

   **Review tab:**
   - Confirm details
   - Click **Request access**

### What Happens Next

The request outcome depends on the customer organization's **Tyler Access** setting in Admin Center:

- **Full access (default)** — Your request is **auto-approved** immediately and appears under **MyAccess** on the dashboard
- **Limited access** — The request goes to **Pending Approval** and the customer Org Admin receives an email with Approve/Deny buttons. They must manually approve before you gain access.

### Access Duration

- Access is **time-bound** and will expire
- You can **extend access** from the request details page via the Actions menu
- Extensions follow the same approval workflow as the original request

### For Support Council Representatives Only

If you are a **Support Council representative** responsible for managing SAC groups for your product team:

1. **Get administrative permissions** from Vijay Venkataraman or Jason Howard
2. **Create SAC user groups** in the `tylertechnologiestx` Admin Center
3. **Associate those groups with CAPM** in the SAC Group Access interface
4. **Add Tyler staff members** to the appropriate groups so they can request access to CAPM

## How Client Administrators Request Access to CAPM

Client administrators **do not "request" access to CAPM** in the traditional sense. Instead, administrators with the appropriate permissions **grant access** to users (including themselves) through **Access Control Lists (ACLs)** in Admin Center.

### Steps for Administrators to Grant CAPM Access

#### Prerequisites
1. **The user must have a Workforce user profile** in **Admin Center > Users** (add them if they don't exist yet)
2. **The user must be able to authenticate** (have valid credentials in an IDP associated with your organization)
3. **CAPM must be available** in your Workspace

#### Creating or Modifying an ACL to Include CAPM

1. Go to **Admin Center > Access Control** (or **Workspaces > [Workspace] > Access Control**)
2. Either click **"Create a new access control list"** or select an existing ACL to modify
3. Enter a **name and description** (if creating new)
4. Select one or more **Workspaces**
5. Select **CAPM** from the available applications list (filterable by name or product)
6. Select the **users** who need access to CAPM (they must already exist in Users)
7. **Review** and **Save**

### Important Notes

- **Organization Admins are not automatically included in ACLs** — even Org Admins must be added to an ACL containing CAPM to access it
- **Only applications that use the ACL model require this step** — CAPM is a workspace application that uses ACLs
- If CAPM doesn't appear in your available applications list, contact **Tyler Support** to have it enabled for your workspace
- ACL updates may take several minutes to process

### Three Conditions Required for Access

For any user to access CAPM (or any workspace application), all three conditions must be met:
1. The user can authenticate
2. CAPM is available in the Workspace
3. The user is in an ACL that contains CAPM

## How Client Administrators Request Access to Admin Center

Client administrators **do not directly "request" access to Admin Center**. Instead, **Tyler implementers provide the initial access** during the organization setup and implementation process.

### How Initial Access is Granted

**Tyler implementers create the first Organization Administrator account(s)** for the customer organization during implementation. The designated administrator(s) will receive a **"Welcome to the Admin Center" email** from `tylerportico.com` that contains:
- Their username
- The Admin Center URL for their organization

### Important Notes About Initial Access

- **Only Tyler employees can create the first Org Admin** — this happens during the implementation/onboarding process
- **The customer cannot self-register for Admin Center** — they must work with their Tyler implementation team
- **Username vs. Email:** The invitation email will state the username to use for signing in. Username and email are separate fields and can differ — use the username from the email, not your email address.

### After Initial Access is Established

Once the first Organization Administrator has access, **they can then add additional administrators and users** through Admin Center:

1. Go to **Admin Center > Users**
2. Add new user profiles for additional administrators or staff members
3. Grant them appropriate permissions (including Org Admin role if needed)

### Password Setup

- If the user receives a separate **"Welcome to Okta!" email** from `[redacted-email]`, follow those instructions to set the Okta account password
- Otherwise, use existing workplace credentials (if the organization has configured SSO with their own Identity Provider)

### Contact for Access Issues

If a customer organization needs initial Admin Center access or has lost access to their admin accounts, they should **contact their Tyler implementation representative or Tyler Support** to have admin accounts created or reset.
