## Removing (Deleting) a Workspace

### For **Internal Organizations** (Tyler-owned):

You can delete workspaces using the Provisioning v2 API or the Ops Center UI:

**API Method:**
- **Single workspace**: `DELETE /api/v2/Tenants/{urlPrefix}` 
- **Bulk delete**: `DELETE /api/v2/Tenants` with a JSON array of `urlPrefix` values

**Required permissions**: Both `delete:workspace` AND `manage:internalorganization`

**UI Method:**
1. Navigate to the organization details → **Manage workspaces**
2. Click the chevron next to the workspace to see its details
3. If you have proper permissions, you'll see **Deactivate workspace** / **Delete workspace** options
4. Enter the workspace key to confirm the action

**⚠️ Important:** 
- **Always deactivate first** (as an observation period) before permanently deleting
- Deletion is **permanent and non-recoverable**
- Deactivation can be reversed; deletion cannot

### For **Customer/External Organizations**:

You **cannot** directly delete these workspaces. Instead:
- **File a OneTyler support ticket** requesting the workspace deletion
- Tyler operations will perform the action through internal tooling on the customer's behalf

---

## Renaming a Workspace

The documentation does **not** describe a direct "rename" operation. The workspace key (`urlPrefix`) appears to be **immutable** once created.

However, you can update the **display name** (`agencyTitle`) which is what users see. This is a field in the `TenantData` that can potentially be updated, though the specific API endpoint for updating workspace properties isn't detailed in the search results.

If you need to truly change a workspace key, the likely approach would be:
1. Create a new workspace with the desired key
2. Migrate the configuration/products
3. Delete the old workspace
