## Gateway Client Secret Rotation

**Quick Answer:**  
Yes, the Gateway supports client secret rotation through the **Client Operations API**. This allows you to generate new secrets with a grace period for the old secret, ensuring zero-downtime credential updates.

### How It Works

When you rotate a client secret:
[REDACTED-CREDENTIAL] A **new secret** is generated and added to your client
2. The **existing secret** remains valid for **3 days** (grace period)
3. Both secrets work during the transition period
4. You can optionally expunge old secrets immediately after updating your applications

### Available Operations

The Client Operations endpoint provides three operations:

- **Rotate Secret** - Generates a new client secret (CCF clients only)
- **Update Redirects** - Updates redirect URIs for login clients  
- **Expunge Old Secrets** - Immediately removes expired secrets

### Security Model

Access is controlled using two layers:
1. An **OAuth2 access token** with the `tidgateway:client-operations` scope
2. A **one-time operations token** unique to each client

Each successful request **consumes** the operations token and returns a **new operations token** for the next call.

### Example: Rotate Secret Request

```json
POST /client_operations HTTP/1.1
Host: server.example.com
Content-Type: application/json

{
  "operation_type": "rotate_secret",
  "client_id": "PEFzc2VydGl",
  "operations_token": "[redacted-secret]"
}
```

**Response:**
```json
{
  "client_secret": "[redacted-secret]",
  "operations_token": "[redacted-secret]"
}
```

### Best Practices

**Use a secure orchestrator service** to manage rotation - applications should **not** rotate their own secrets directly. This enforces:
- **Separation of Duties**
- **Least Privilege** principles

Your orchestrator should:
- Store operations tokens securely
- Manage the rotation schedule
- Distribute updated configurations to applications

### Getting Started

1. Identify your manually created `tid-gateway` client
2. Submit a ticket to the Tyler Identity Team with:
   - **Identity Client Name**: your existing client name
   - **Identity Client Request Type**: "Enable Client Operations"
3. Wait for the first operations token (sent via Kiteworks)
4. Implement the API calls in your orchestrator

**Note:** This feature is for **manually created Gateway clients** only. Okta clients are not supported.
