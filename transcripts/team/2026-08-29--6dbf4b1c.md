**Q:**

> How should I test the configuration for my product in release manager?

**A:**

```markdown
I'll search the knowledge base for information about testing product configurations in Release Manager (the Aligned Releases system).Based on the knowledge base, I can help you understand how to test your product's configuration in Release Manager. Let me clarify what testing means in this context:

## Testing Your Product Configuration

**Product registration** is managed in **Ops Center Product Registry**, not Release Manager itself. Release Manager uses your `productRegistrationId` from that registration.

### What to verify:

1. **Product Registration ID**
   - Confirm your `productRegistrationId` exists in Ops Center → Product Registry
   - This is shown as `pbb` in the Registration details section
   - This ID is required for all API calls and feature creation

2. **Identity Client Setup (for API integration)**
   - Request an Identity Client per environment using the [Identity Client ticket form](https://help.center.tylertech.com/servicedesk/customer/portal/3168/group/3329/create/4153)
   - **One client per environment** — file separate tickets for TCPCI (dev), TCPQA, and Production
   - The client must be **associated with your product** for permissions to work
   - Start testing in **TCPCI (dev)** environment first

3. **Test via the Integration Checklist**

   From the **Integration Checklist**, validate:
   
   - ✅ You can obtain OAuth 2.0 token with `client_id` and `client_secret`
   - ✅ Your `productRegistrationId` is confirmed
   - ✅ You can create a test feature via `POST /api/v1/feature`
   - ✅ The feature returns successfully in `Planned` state
   - ✅ You can query features for your product via `GET /api/v1/feature`

4. **Available Environments**

   Test in this order:
   - **TCPCI** (dev) — `https://api.tcpci.com`
   - **TCPQA** — `https://api.tcpqa.com`
   - **Production** — `https://api.tylercloud.com`

### What Release Manager Does NOT Test

- Release Manager is **not a test harness** for product functionality
- It manages the feature lifecycle and cohort assignments
- **Deploying code and activating features are separate** — your product can deploy any time; Release Manager controls when impactful features are activated by cohort

### Resources

The official integration checklist is currently under construction at https://docs.tylerdev.io/aligned-releases/integration-checklists/aligned-releases-checklist, so use the workflow steps in the Integration Guide as your practical checklist.
```
