> Can products start using SAC?

**A:**

```markdown
I'll search the knowledge base to find information about when products can start using SAC (Support Access Center).

Based on the knowledge base, yes, products can start using SAC (Support Access Center), but they must meet specific engineering requirements first.

## Requirements for Products to Adopt SAC

A product that wants to adopt SAC must meet **all** of the following engineering requirements:

1. **Integrated with Identity Workforce (Gateway)** - SAC is not supported over Workforce Managed + Okta.

2. **Registered in the Tyler Cloud Platform** - This includes any application definitions that expect to check user access.

3. **Indicate in product registration that the product has adopted SAC** - *(Note: This capability is not yet available but will be added in the future.)*

4. **Adopt the Security API (`tcp-login-security-api` v1)** - The product must query whether a user has access to your application on a given workspace using:
   - Endpoint: `GET /platform/login-security/api/v1/checkaccess/{sub}/workspace/{workspaceKey}/app/{appRegistrationId}`
   - For SAC, the relevant response fields are:
     - `supportAccess.hasAccess` / `supportAccess.expiresOn`
     - `supportAccessUserGroups`
   - Other fields (`userIsMemberOfOrg`, `productGroupAccess`, `userGroups`) are **not used by SAC**

## Important Compatibility Note

SAC is **not compatible with all combinations** of Organization Identity Tier and Workspace OnPrem target, so products should verify compatibility before integration.
```
