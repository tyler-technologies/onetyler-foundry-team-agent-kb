## What is a Workspace?

A **Workspace** is a **logical construct** that groups Tyler solutions together for a given customer organization and business use (e.g. production use, test use, etc.), regardless of each solution's hosting environment(s). All product instances, datasets, and integrations participating in that customer and business use are tagged with the same workspace key to provide customers with a "single pane of glass" experience, both within products and across products.

### Core Definition
- A **logical construct** independent of product tenancy, datasets, and integrations
- All deployments/provisioning across Tyler must be tagged with a workspace key
- When installing multiple instances of a product for production use, all instances get the same workspace key.
- By default, we allow a single production workspace and 6 non-production workspaces
- Represents a "customer business purpose"

### Key Characteristics
- **Provisioned by Tyler** — customers cannot create new workspaces themselves through Admin Center
- Groups Tyler solutions consistently across different hosting environments
- Some platforms (like Tyler Cloud Platform/TCP) can host all of a customer's workspaces (prod/test/train/staging) in one environment with virtual data segregation

### Workspace Components
Within a workspace, you can manage:
- **Access Control Lists (ACLs)** — control who can access what applications
- **Apps** — lists apps that require ACL-based access
- **Links** — customize footer links for community-facing applications
- **Contacts** — set business and technical contacts
- **Banner** — for NonProduction workspaces, set visual banners to distinguish from production

### Identifiers
- Each workspace has a unique **Workspace ID** (`portalId` / `workspaceKey`)
- Production workspace key is the same as `{orgKey}` and the 6 standard non-production workspaces have keys of the form `{orgKey}-{test|train|staging|impl|uat|dev}`
- Has a configurable title that controls Community App Directory banner text and navigation

If you need a new workspace or find one missing, use Ops Center to create workspaces. Alternatively you can use our APIs integrated with your deploy tools to create workspaces (e.g. Tyler Deploy and Cloud Provisioner).
