# FAQ — Support Access Center

Source: **authored in this repo — no upstream document.** `Docusaurus-SupportAccessCenter.md`
is derived from Tyler Blueprint and is re-derived when Blueprint changes. This file is the
**home of record** for SAC answers that exist nowhere else.

Domain: Support Access Center (SAC)
Audience: Tyler operational, support, engineering and Support Council staff.

**Companion:** `_START_HERE.md` for routing. For "which ticket do I file", use
`Knowledge-Shared/Conf-OneTylerTickets.md` — including the two SAC entries there (*Enable
Support Access Center on a Workforce Managed org* and *Be authorized to use Support Access
Center for a product*).

---

## What belongs here

- Answers given verbally by a subject-matter expert that are not written down anywhere.
- Behaviour learned by observation or testing that no document describes.
- Corrections to an upstream source the owner has not yet fixed.
- Group-administration and eligibility judgements that are decided case by case rather than
  documented.
- Recurring questions from real transcripts whose answer had to be assembled from scratch.

## What does NOT belong here

- Anything already in Blueprint's SAC documentation — it belongs in
  `Docusaurus-SupportAccessCenter.md`, so it is re-derived when Blueprint changes.
- Ticket forms and authorization requests — `Knowledge-Shared/Conf-OneTylerTickets.md`.
- Speculation. If nobody has confirmed it, leave it out; the agent will state it as fact.

## Entry format

```markdown
### Q: <the question, phrased the way a user would ask it>

**A:** <the answer>

- **Source:** <who said it / where it was observed — name a person or a verifiable check>
- **Added:** <YYYY-MM-DD> by <github username>
- **Confidence:** confirmed by owner | provisional — needs confirmation
- **Promote when:** <the upstream doc that should eventually carry this, if any>
```

Keep entries self-contained — retrievers chunk independently of headings.
